## Decisions

- **Persistence**: Postgres via Drizzle. Hosted on Neon (free tier) in production; the Neon–Vercel integration gives each preview deploy its own database branch. Switched from DynamoDB before any storage was built: a real database gives Better Auth stable user IDs and server-side sessions, previews get isolated data without AWS setup, and sharing/cross-plan features are plain SQL
- **Config (12-factor)**: everything environment-specific comes from env vars (`DATABASE_URL`, auth secret and URL, Google client, plan cap), documented in `.env.example`. How Postgres runs locally (Homebrew, Docker, Neon branch) is up to the developer
- **Hosting**: Vercel (Hobby). Staging = previews (protected) on a fixed `staging` domain; production from `main`
- **Accounts**: Better Auth with Google sign-in, stored in Postgres. Open sign-up with a per-user plan cap (`MAX_PLANS_PER_USER`, default 2). Users only see plans they're a member of
- **Tests**: storage tests run on PGlite (in-process Postgres), so `pnpm test` needs no database; browser tests use Better Auth's `testUtils` from a test-only auth config, never a login route
- **Node version**: 22 via mise (required by vitest 4)
- **Gym tracking**: out of scope for v1 — model supports it, UI ignores it
- **Blocks**: user-defined via `blockStarts` (ISO Mondays), edited in an "Edit blocks" mode; cosmetic only (no effect on calculations)
- **Future features to keep in mind**: move workouts, bulk updates, copy/paste, undo (don't design these out)
- **Activity status**: `status?: "completed" | "missed"` on Activity (undefined = pending). Missed activities excluded from all load calculations.

## Next steps: persistence, accounts, deploy (#6)

Goal: cheap to run (~$0 at personal scale) and able to grow into sharing.

### Schema

```
user, session, account, verification   ← generated by Better Auth (6c)
plans          id, name, start_date, week_count, prior_weekly_distances,
               block_starts, version, created_at, updated_at
plan_members   plan_id, user_id, role ('owner' | 'editor' | 'viewer')   (6c)
activities     id, plan_id, date, type, run_type, name, distance,
               intense_distance, status
```

- Saving stays "save the whole plan": one transaction that updates the plan only if `version` still matches (otherwise a conflict error, so a stale tab can't overwrite newer edits), then replaces its activities.
- Home lists plans you're a member of; loading or saving checks membership (6c). Sharing later = adding a `plan_members` row.
- Existing plans keep their IDs on import; new plans get UUIDs.

### Steps

- **6a CI**: GitHub Actions on every PR and push to main: typecheck, lint, vitest.
- **6b Postgres storage**: Drizzle schema + migrations, `lib/plan-store.ts` rewritten on Postgres with the version check, storage tests on PGlite, and `scripts/import-plans` to load `data/plans/*.json`. Same single-user behaviour as today.
- **6c Accounts**: Better Auth (Drizzle adapter) with Google sign-in, sign-in page, `plan_members` with ownership checks in every page and server action, plan cap. Import/claim assigns existing plans to your user by email. Ownership is a `plan_members` row with `role: "owner"`; users and sessions are Better Auth's tables. `pnpm db:claim <email> [ids]` gives unowned (imported) plans to a user who has signed in once. Pages and server actions check membership server-side (no `proxy.ts`; Next's docs treat proxy as an optimistic check only).
- **6d Deploy**: Vercel project + Neon integration (prod database, branch per preview), production Google client, Better Auth `oAuthProxy` so sign-in works on preview URLs, staging domain.
- **6e Browser tests**: Playwright against a production build, logging in via `testUtils`; smoke tests against staging after deploy.

Packages: `drizzle-orm`, `drizzle-kit`, `pg`, `@electric-sql/pglite`, `better-auth` (6c), `@playwright/test` (6e).
